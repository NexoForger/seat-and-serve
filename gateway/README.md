# Store gateway prototype

Node 22+ and HTTPS are required. Set `TRT_GATEWAY_CERT`, `TRT_GATEWAY_KEY`, `TRT_GATEWAY_TOKEN`, `TRT_GATEWAY_DB`, `TRT_SITE_URL`, `TRT_SITE_API_TOKEN` (`key:secret` for a dedicated Frappe service user), and `TRT_OUTLET`. Start with `npm start`.

The gateway records staff order commands and accepted cash in SQLite before acknowledging them. `/refresh` copies the outlet catalog from Frappe; `/sync` replays pending order commands with the same event IDs. Cash commands require a configured `mode_of_payment`. After all cash has been physically accepted, send one `settle_cash` command for the order. `/sync` then calls ERPNext `cash_checkout` with that event ID and all recorded tenders; it marks the local order Settled only after ERPNext confirms a submitted POS Invoice. A timeout leaves the event pending for an idempotent retry, while a price, shift, tax, or tender mismatch becomes a visible conflict. The gateway service user must have the outlet's cashier assignment and an open POS shift. `/state` exposes local orders, shared kitchen tickets, and event conflicts. `/ticket` advances a local ticket with an event ID and expected revision. All routes require `Authorization: Bearer <TRT_GATEWAY_TOKEN>`. Device simulators respond at `/device/simulate`.

For an ASCII ESC/POS kitchen printer, set `TRT_KITCHEN_PRINTER_ADDRESS` to its fixed IPv4 address and optional port (default 9100), then POST `{ "ticket_id": "...", "reprint": false }` to `/device/kitchen/print`. For a cash drawer connected to an ESC/POS printer, set `TRT_DRAWER_PRINTER_ADDRESS` and POST `{ "order_id": "..." }` to `/device/drawer/open` after recording accepted cash. These endpoints use the same bearer token, accept only stored orders and tickets, and never accept arbitrary printer bytes or network destinations. A successful socket write does not prove paper printed or a drawer opened. The kitchen text driver accepts ASCII only; use a raster-capable, model-certified driver before printing Arabic tickets.

This remains a development prototype. It does not sync local kitchen status, calculate authoritative offline tax, resolve price conflicts, coordinate multiple gateway processes, or certify real devices. Keep it off a live LAN until those controls are implemented and tested.
